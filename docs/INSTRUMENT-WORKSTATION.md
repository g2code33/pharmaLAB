# Organ bath workstation

## What changed

The default route is Laboratory, not Dashboard. A fresh, unsaved guinea-pig ileum experiment is immediately usable. New experiment creates a different notebook ID; Save writes only the active notebook. Save before starting a different session. Navigating to Resources pauses acquisition but retains the draft, dosing inputs, elapsed time, events, and recording scale. Return via Laboratory. Reopening a saved record does not simulate time spent away.

`main.tsx` still owns the experiment, local preferences and existing notebook/report routes. The former permanent navigation rail is now a compact header. `laboratory/ProtocolBench.tsx` is the primary control rack and three-tab workstation, not an additional destination. `TraceScreen.tsx` draws a graticule, acquired samples and timed events. `ProtocolNotebook.tsx` consolidates the existing evidence, local fit, exposure analysis and export tools. `workstation.css` adds the instrument skin and responsive drawer. The existing Bath SVG, ProtocolPlot, CurveReview, EvidenceReplay, catalogues, IndexedDB/SQLite adapters, service worker and dependency stack remain in use. Legacy bath-only notebooks still use their dose controls and RecordingPlot; that plot does not supply physiological force.

## Controls and scientific boundaries

* **Manual dose:** choose ACh stock (M/mM/µM/nM) and volume (mL). Preview and replay use `mix()`, including existing drug and the increased final volume. The calculator edits the very same inputs. The supported input bounds are numerical guardrails, not experimentally measured solubility or glassware capacity. Scheduled protocols retain their original target-dose logic and do not accept extra manual additions.
* **Reservoir:** Prepare sets the nominal ACh concentration of an ideal replacement solution, independent of the bath. Clear makes the reservoir drug-free, leaving bath volume, drug and tissue untouched. Flush fully exchanges the bath at its configured initial volume and recorded reservoir concentration. Wash uses drug-free solution. These are instantaneous ideal exchanges, not a validated flow/dead-volume model. Multiple commands within one virtual second are applied in insertion order before the next tissue step.
* **Setup:** the selected preparation provides its recipe, bath volume, load, temperature and gas. Before a run, bath volume changes mass balance; load sets the passive component for an explicitly scaled recording. Recipe overrides are recorded as metadata, not used to infer any ion-dependent change in potency. Included recipes are the repository's cited Krebs and Tyrode, not an invented Krebs-Henseleit formulation. Gas, temperature and equilibration have no adjustable physiological model. No electrical stimulation, antagonists, unknown-drug experiments or 3D renderer are activated.
* **Chart:** Record advances virtual time. Pause freezes it; Stop closes the run. Optional delayed acquisition leaves earlier samples out of the trace and signal export, not out of tissue history. Window start, window size and zoom change the view, not the samples. Relative response is % of scenario scale, not measured force; optional grams include the explicitly assumed force scale. The baseline has zero active response. Dose, wash and time-stamped annotation markers use virtual seconds. Playback, point inspection and saved overlays are under Timeline & inspection.
* **Persistence:** `GP-ACH-001/option-a-2` adds bounded stock/volume transfers, exchange composition, initial bath volume, solution override, and acquisition start. The envelope checks the embedded plan revision; unedited older runs retain their revision. The original `optionA.advance` tissue equations, `mix`, and source registries are unchanged. No database migration is required. The UI does not create calibrated force samples or independently validate the model.

## Verification

`npm run check`, `npm test`, `npm run build`, `npm run verify:web`, and `npm run test:e2e` (with an installed Chromium). Existing browser scenarios now use the compact navigation. Additional tests exercise invalid doses, physical mass balance, reservoir/bath independence, recipe selection, chart markers, stopped state, mobile controls and retained inputs. Native installer qualification is separate; no new desktop dependencies or storage implementation were introduced.
