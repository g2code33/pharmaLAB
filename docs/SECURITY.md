# Release trust boundary

PRs have read-only repository tokens, no publication jobs, no imported signing keys. Checkout does not persist Git credentials. Build caches contain dependency sources, not credentials or executable release directories. CI uses npm ci/integrity hashes, a locked Cargo graph, npm audit, RustSec audit, Git-history secret scanning with redaction, strict TypeScript checks, native Clippy and frontend licence notice collection. Audit services require network availability. Failure to fetch or run a scanner is not a passing audit. Security warnings and unsupported system libraries still require human review.

Windows signing is optional. On a trusted repository configure Actions secrets `WINDOWS_PFX_BASE64` (encoded code-signing PFX) and `WINDOWS_PFX_PASSWORD` using GitHub's secret UI or `gh secret set NAME < protected-file`; never type secret values into commands, commit them, or submit them to chat. Restrict who can modify workflows and release refs. For production certificates prefer environment scoping restricted to allowed main/tag refs or a future hardware-backed signing service. Partial credentials fail. On an eligible Windows runner the signing step imports the key into the ephemeral current-user store, deletes the temporary PFX, and passes only the certificate thumbprint to Tauri. The verified signature on both installer and installed executable is required before marking an artifact signed. Unsigned builds carry an explicit suffix and warning; they do not establish publisher identity. Never disable SmartScreen to make a test pass. Debian and web assets are checksum-verified, not publisher-signed.

The web runtime needs no API, sessions, tokens, cross-origin credential requests or admin endpoints. Local scripts only; the production CSP prohibits object embedding, foreign connections and form posts. Inline style remains needed by the current UI. No external script or eval grant. Tauri uses its own IPC-aware CSP and only the main webview’s read_record and write_record commands; do not load remote web content into it. No arbitrary SQL is accepted from JavaScript: treat any new renderer input or plugin as a trust-boundary change. React renders notebook strings as text; import schema checks run before storage. Backups may contain private research notes; release jobs must not collect local user databases. Never disable sandboxing, certificate verification or checksum checks.

Release permissions are scoped to the final trusted job. Protect main and version tags, configure reviewers for `production`, and review repository/org Actions policy before granting publication. Hashes alone cannot defend against repository/admin compromise. Toolchain and OS security updates, certificate renewal, native licence review, reviewer setup, and testing on real end-user hardware remain operator responsibilities.
